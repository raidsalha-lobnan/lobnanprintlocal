# ترحيل أصناف البرنامج — 105 فواتير معتمدة

هذه تعليمات تشغيل **على الكمبيوتر الرئيسي نفسه** في نافذة PowerShell للمسؤول. لا يُشغَّل الأمر تلقائيًا أو من خلال عميل ويب.

## نطاق التنفيذ

- الاحتفاظ بالفواتير الـ105 المعتمدة، بما فيها الكميات والأسعار والخصومات والمدفوعات والإجماليات.
- تحويل 29 سجل صنف إلى 28 صنفًا فعليًا، بدمج سجلَي `PRI-0015` في السجل المرتبط بالفاتورة والأسعار الخاصة. حفظ أصل السجل المنتهي في أرشيف تدقيق، وتحويل المراجع بمعرّف الصنف.
- 25 صنفًا ضمن `PRI`، وصنفان ضمن `BOK`، وصنف واحد ضمن `ACC`. الكود الجديد ثابت.
- أرشفة أوامر الطباعة الـ102 التي لا ترتبط بالفواتير المعتمدة. الاحتفاظ بقيد اليومية الأصلي وإضافة 48 قيدًا عكسيًا بقيمة 1,311 ₪.
- حساب الإيرادات `4102`: الرصيد المخزن 1,300 ₪ بينما أرصدة قيود أوامر الطباعة 1,311 ₪. يعيد الترحيل احتساب الرصيد من أصل القيود والقيود العكسية، ولا يخصم المبلغ مباشرة من الرصيد المحفوظ.
- الاحتفاظ بالأكواد السابقة للبحث ومسح الباركود؛ منع إعادة استخدامها لصنف آخر.

## شروط لا يجوز تخطيها

1. يجب أن **تكون جميع الأجهزة قد أنهت المزامنة** وتظهر طوابير الأوفلاين فارغة. وإلا قد تعود قيود أو فواتير قديمة عند إعادة الاتصال.
2. أوقف مؤقتًا دخول المستخدمين، وأغلق برنامج المحاسبة على جميع الأجهزة. أوقف خدمة الـ API التي تستمع على `localhost:4577` فقط، **ولا توقف PostgreSQL** على المنفذ 5432.
3. شغّل الأداة في نفس حساب Windows الذي يملك ملف بيانات اتصال PostgreSQL المشفر محليًا. الأداة لا تعرض كلمة المرور في المخرجات.
4. الأداة تُنشئ نسخة احتياطية جديدة تلقائيًا وتتحقق من شكلها؛ ثم تختبر الترحيل في معاملة متراجَع عنها قبل طلب تأكيد التنفيذ.
5. إذا أُضيفت فاتورة جديدة، أو تغيّر عدد الأصناف أو الحركات أو أوامر الطباعة، **تتوقف العملية** تلقائيًا. لا تُغيّر الأرقام المتوقعة يدويًا؛ أعد التدقيق أولًا.
6. يجب حماية ملف النسخة الاحتياطية لأنه يحتوي بيانات مالية وغير مشفّر في مكانه المحلي.

## التشغيل

من مجلد المشروع `C:\Users\RaidSalha\lobnan-cloud-preview` في PowerShell:

```powershell
# للعرض فقط دون تطبيق أي تغيير
.\scripts\execute-approved-catalog-migration.ps1

# محاكاة مدققة (Rollback)، بعد إيقاف API
.\scripts\execute-approved-catalog-migration.ps1 -DryRunOnly

# التنفيذ بعد نجاح الاختبار والتأكيد اليدوي مرتين
.\scripts\execute-approved-catalog-migration.ps1 -Apply
```

تُوقف الأداة العمل عند أي خطأ أو اختلاف في الشروط. عند النجاح يجب أن تعرض: **105 فاتورة، 28 صنفًا، صفر أمر طباعة نشط، 48 قيدًا عكسيًا**.

بعد النجاح أعد تشغيل API وراجع سجل المزامنة، ثم انشر نسخة الواجهة من الفرع `feat/catalog-reclassification-preflight` بعد نجاح اختبارات GitHub ومراجعتها. لا تدمج الفرع أو تنشره قبل تحديث قاعدة البيانات.
